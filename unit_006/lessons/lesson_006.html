Lesson Examples - Polymorphism and Abstraction

These examples introduce polymorphism (same method name, different behavior) and abstraction (exposing what is needed while hiding messy details).

Polymorphism and Abstraction

  • Polymorphism: Different objects respond to the same method name in their own way.
  • Abstraction: Hide complex internals; offer a simple, clear interface.

Example 1: Polymorphism Through Method Overriding 

class Shape:
    def area(self):
        return 0

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side * self.side

shapes = [Circle(3), Square(4), Circle(1)]
for s in shapes:
    print(round(s.area(), 2))

Output:

28.27
16
3.14

Same method name (area), different calculations.

Example 2: Duck Typing in Python

Python often cares more about behavior (“does it have this method?”) than about a strict family tree.

class Printer:
    def render(self):
        return "Sending to printer..."

class Screen:
    def render(self):
        return "Drawing on screen..."

def show(device):
    # No shared parent required — just needs render()
    print(device.render())

show(Printer())
show(Screen())

Output:

Sending to printer...
Drawing on screen...
Tip: “If it walks like a duck and quacks like a duck...” — if it has the needed method, Python can use it.

Example 3: Abstraction — Simple Interface, Hidden Details 

class TemperatureSensor:
    def __init__(self, celsius):
        self._celsius = celsius  # internal detail

    def reading_f(self):
        """Public interface: user does not need the conversion formula."""
        return (self._celsius * 9 / 5) + 32

    def status(self):
        f = self.reading_f()
        if f < 32:
            return "Freezing"
        if f > 85:
            return "Hot"
        return "Comfortable"

sensor = TemperatureSensor(22)
print(sensor.reading_f())
print(sensor.status())

Output:

71.6
Comfortable

Callers use clear methods instead of reimplementing conversion logic themselves.

Example 4: Prefer Methods Over Raw Internals 

class Playlist:
    def __init__(self):
        self._songs = []

    def add(self, title):
        self._songs.append(title)

    def count(self):
        return len(self._songs)

    def titles(self):
        return list(self._songs)  # return a copy

pl = Playlist()
pl.add("Hymn of Praise")
pl.add("Psalm 23")
print(pl.count())
print(pl.titles())

Output:

2
['Hymn of Praise', 'Psalm 23']
Abstraction does not mean “never look inside.” It means design a clear public face so most code does not depend on fragile internals.
