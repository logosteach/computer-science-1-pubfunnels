Lesson 004 - IDLE Script Editor — Talking Points

Key talking points and discussion notes for teaching creating, saving, and running multi-line scripts in IDLE, with comments and simple debugging.

Main Teaching Points

  • New File in IDLE: Editor window vs shell window.

  • Save as .py + F5: Run Module workflow.

  • Why scripts exist: Persistence, homework, multi-line logic.

  • Comments: Explain why; keep them accurate.

  • Debug loop: Error → edit → save → run.

  • Doers of the Word: James 1:22–25—living response, not one-time hearing.

Discussion & Talking Points

  • Question 1: What steps turn a new IDLE window into a runnable program?

  • Question 2: Why save before Run Module?

  • Question 3: When is the shell better than a script, and vice versa?

  • Question 4: Write a two-line script with one comment and one print.

  • Question 5: How does re-running a corrected script relate to being a doer of the Word, not a hearer only?

Biblical Integration

Scripts call us to write, save, and do—not only to experiment once and forget. James urges us to be doers of the Word, not hearers only. Building lasting faithfulness matters more than momentary impulses.

Scripture (NKJV):
“But be doers of the word, and not hearers only, deceiving yourselves… But he who looks into the perfect law of liberty and continues in it, and is not a forgetful hearer but a doer of the work, this one will be blessed in what he does.” (James 1:22, 25, NKJV)
