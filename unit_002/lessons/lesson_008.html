Lesson Examples - Comments and Types of Errors

These examples show how to write clear comments and how comments help document purpose. They also introduce common error categories you will meet while learning Python.

Inline Comments with #

Everything after # on a line is ignored by Python. Use comments to explain why, not to restate the obvious.

Example 
# Calculate total after tax
price = 20.00
tax_rate = 0.07  # 7% sales tax
total = price * (1 + tax_rate)
print(total)

Output:

21.4

Multi-line (Paragraph) Comments

Triple-quoted strings are often used as multi-line documentation or temporary block notes at the top of a practice file.

Example 
"""
This practice program shows simple tax math.
Learning goals: variables, expressions, comments.
"""
print("Ready to practice")

Output:

Ready to practice
Tip: Triple-quoted text is a string expression. At the top of a file it is common for a module docstring; inside code, prefer # for true comments unless you intend a string.

Best Practices for Comments

Write for a classmate six months from now. Keep comments short, accurate, and updated when code changes.

Example 
# Good: explains purpose
hours = 3  # hours spent on the lab

# Weak: only repeats the code
hours = 3  # set hours to 3

print(hours)

Output:

3

Types of Errors (Overview)

Knowing error categories helps you fix problems faster.

Example 
# SyntaxError example (invalid Python):
# if True print("hi")

# Runtime NameError example:
# print(undefined_name)

# Runtime TypeError example:
# print("3" + 3)

print("Syntax errors stop the program before it runs.")
print("Runtime errors happen while the program is running.")
print("Logic errors run but produce wrong results.")

Output:

Syntax errors stop the program before it runs.
Runtime errors happen while the program is running.
Logic errors run but produce wrong results.
Watch out: Logic errors are the hardest: no crash, wrong answer. Testing and reading carefully matter.
