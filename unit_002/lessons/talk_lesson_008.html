Lesson 008 - Comments and Types of Errors — Talking Points

Key talking points and discussion notes for teaching inline and multi-line comments, comment best practices, and introducing common error types.

Main Teaching Points

  • # inline comments: Explain why / intent, not noise.

  • Triple quotes: Docstrings vs. casual multi-line notes.

  • Comment hygiene: Keep them true when code changes.

  • Error categories: Syntax, runtime (NameError, TypeError, ValueError), logic.

  • Paul’s clarification: 1 Cor 1:14–16 as a pastoral parallel for preventing misunderstanding.

Discussion & Talking Points

  • Question 1: What is a helpful comment vs. a redundant one?

  • Question 2: Why should you update comments when you change code?

  • Question 3: Give an example of a syntax error and a logic error.

  • Question 4: How does a clear comment protect future readers?

  • Question 5: How does Paul’s clarifying note in 1 Corinthians 1 model careful communication?

Biblical Integration

Comments clarify so readers do not misunderstand. Paul sometimes inserts clarifying explanations so the church would not draw the wrong conclusion about his ministry.

Scripture (NKJV):
“I thank God that I baptized none of you except Crispus and Gaius, lest anyone should say that I had baptized in my own name. Yes, I also baptized the household of Stephanas. Besides, I do not know whether I baptized any other.” (1 Corinthians 1:14–16, NKJV)
