# Creating A Computer Lab Rules

When creating a computer lab, generate a **Microsoft Word document** (`.docx`). Do **not** generate a PDF for a new computer lab unless the instructor explicitly asks for a PDF.

Word documents can be edited later by the instructor. That is the point of the change.

---

## File format

- Deliverable: one `.docx` file.
- Keep the lab and the solutions in **the same file**.
- After the student pages, start a **new page** titled for the instructor (for example, "Teacher Notes and Sample Responses").
- Do not add a grade scale.
- Scripture is NKJV only. Use a verse that already belongs to the lesson. Do not invent a text.

A lab will sometimes be 15 minutes in length but not always. Ask the instructor ahead of time if the length is not specified.

---

## Where to save

| Repository | Folder | Example |
|---|---|---|
| `logosteach/computer-science-1-pubfunnels` | `unit_00N/computer_labs/` | `unit_002/computer_labs/Why_Data_Types_Are_Needed_Research_Lab.docx` |
| Session project | `artifacts/` and `artifacts/unit_00N/computer_labs/` when that unit folder exists | same file name |

Use a clear Title_Case or snake-free descriptive name that matches the lab topic. Use the same file name in every copy.

## Page chrome (match existing CS1 labs)

- US Letter.
- Header bar navy `#0D3358` with a gold `#E1A244` rule.
- Header text left: `LogosTeach  ·  Computer Science 1  ·  Unit NNN`
- Footer bar `#E8EEF3` with a gold hairline. Left copyright. Right page number.
- Body text about 11 pt, dark ink `#222222` or `#2A2A2A`. Calibri or Arial is fine in Word.
- Code, if any, in Consolas or Calibri on `#E7F2FD`.
- Title band: rust kicker, gold title field, short promise sentence, time box.
- Scripture in italic NKJV on an ivory `#FFF9F0` callout with the reference in teal `#1A7070`.
- End with the required Grok collaboration sentence.

Reuse the look of `Jenna_and_Jayne_Bake_Sale_Revenue_Lab.docx`. Do not invent a new brand.

---

## Required lab sections — in this order

1. Banner — unit, lesson, COMPUTER LAB kicker, title, one-sentence promise, time box.
2. Objectives — three to five observable verbs. No grade scale.
3. Scenario — one named character, one concrete job.
4. Tasks — numbered. Each task has a minute mark.
5. Deliverable — what to save or show. Address the student working **alone** and the student working **with an instructor**.
6. Scripture — NKJV only.
7. Close — copyright line and the Grok collaboration disclaimer.
8. New page — teacher notes, sample responses, common mistakes, and discussion help.

---

## Research labs

A research lab is still a computer lab. Students read, cite sources, write in their own words, and talk. They may not write much Python.

For a research lab include:

- The research question in plain language.
- A rule to **cite sources** (author or site name, title, and URL or book page).
- Space to write one or two paragraphs.
- A close that asks for **at least two further questions** the student still wants answered.
- A prompt for class or group discussion.

Do not write the student's paragraphs for them on the student pages. Put sample language only on the teacher page.
