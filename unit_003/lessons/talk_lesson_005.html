Lesson 005 - Python Dictionaries — Talking Points

Key talking points and discussion notes for teaching Python dictionaries: key–value pairs, access and update patterns, iteration, common methods, and when a dict is the right structure.

Main Teaching Points

  • Key–value model: Dictionaries map a meaningful key to a value (like a phone book). Lookup is by label, not by position.

  • Create and mutate: Use {} or filled literals. Add or change with d[key] = value; remove with del d[key].

  • Safe access: d[key] raises KeyError if missing. d.get(key, default) is safer when the key may not exist.

  • Core methods: keys(), values(), items(), update(), and get() cover most beginner tasks.

  • Looping: for key in d, for v in d.values(), and for k, v in d.items() are the three patterns students should practice.

  • When to choose a dict: Labeled records, configuration, counts by category, any time “look up by name/id” is clearer than remembering index numbers.

  • Key rules: Keys must be unique and immutable (strings/ints common). Values can be many types.

Discussion & Talking Points

  • Question 1: How is looking up student["score"] different from looking up student_list[1]? Which is easier to maintain six months later?

  • Question 2: When would you still prefer a list or a tuple over a dictionary?

  • Question 3: Why does get() matter in real programs that read optional data (forms, configs, user input)?

  • Question 4: Walk through a mini design: store three campers with name, cabin, and age. Why is a dict (or a list of dicts) natural here?

  • Question 5: Dictionaries retrieve values by meaningful keys. How does that parallel the truth that God knows and calls His people by name?

Biblical Integration
