Lesson 001 - Modules and Import Statements

Modules let us organize code into reusable files and bring in tools written by others—both from Python’s standard library and from the wider programming community. In this lesson you will learn what modules are, how to use import and from ... import ..., and how those two styles differ. Just as God has gifted different members of the body of Christ with different abilities for the good of all, modules remind us that we do not build alone.

What Are Modules and Why Are They Useful?

A module is a Python file (ending in .py) that contains related code: functions, variables, classes, or constants that you can reuse. When you import a module, you make that code available in your current program without rewriting it.

Modules are useful because they help you:

  • Reuse code — write once, use in many programs
  • Organize projects — keep related tools in separate files
  • Build on the work of others — use the standard library and community packages
  • Avoid reinventing the wheel — math, dates, random numbers, and more are already written for you
Example: Using the built-in math module 
import math

print(math.pi)           # 3.141592653589793
print(math.sqrt(16))     # 4.0
print(math.ceil(3.2))    # 4
print(math.floor(3.8))   # 3
Tip: Python ships with a large standard library of modules (math, random, datetime, os, and many more). You do not need to install these—only import them.

Using import to Bring in a Module

The simplest form is import module_name. After that, you access items with module_name.item (dot notation). This style keeps the module’s name attached to every use, which makes it clear where each function came from.

Import an entire module 
import random

# random is the module; randint and choice are functions inside it
print(random.randint(1, 6))          # a die roll: integer from 1 to 6
print(random.choice(["A", "B", "C"]))  # picks one item from the list
Import and use the datetime module 
import datetime

today = datetime.date.today()
print(today)                         # e.g., 2026-07-21
print(today.year)                    # 2026
print(today.strftime("%B %d, %Y"))   # e.g., July 21, 2026
Import with an alias (shorter name) 
import datetime as dt

now = dt.datetime.now()
print(now.hour)                      # current hour (0–23)

Aliases (with as) are optional. They are handy for long module names or when a community convention exists.

Built-in vs. external modules

Not every module comes with Python. You will work with two kinds:

  • Built-in / standard library modules — included with Python (math, random, datetime, os). Use import only; no install step.
  • External modules (packages) — written by the wider community and installed separately (for example with pip). After installation, you import them the same way as built-in modules.
External module pattern (concept example) 
# In a terminal (one-time install — do not put pip in your .py file):
#   pip install requests
#
# Then in your Python program:
import requests

# Same import style as a built-in module; the tools came from the community
response = requests.get("https://api.github.com")
print(response.status_code)   # 200 means the request succeeded
Tip: The import statement itself does not change for external modules. What changes is that someone else created the package and you install it first. That is community software: gifts of skill shared for others to use.
Note for this course: Most early lessons stay with the standard library so you can practice without installing extra packages. When we use an external module later, the lab will tell you exactly what to install.

Importing Specific Functions with from ... import ...

Sometimes you only need one or two items from a module. You can import them by name and then call them without the module prefix:

Import specific names 
from math import sqrt, pi

print(sqrt(25))    # 5.0  — no math. prefix needed
print(pi)          # 3.141592653589793
Import one function and use it directly 
from random import choice

fruits = ["apple", "banana", "cherry"]
print(choice(fruits))   # e.g., banana
Import with a local alias 
from math import factorial as fact

print(fact(5))     # 120  (5 × 4 × 3 × 2 × 1)
Tip: Prefer importing only what you need when the module is large and you use just a few names. Prefer import module when you use many items from that module, so readers can see the source at a glance.

Comparing import module and from module import name

Both styles give you access to the same code, but they differ in how you write calls and how clear the origin of each name is.

Side-by-side: same task, two styles 
# Style A: import the whole module
import math
print(math.sqrt(9))
print(math.pi)

# Style B: import only what you need
from math import sqrt, pi
print(sqrt(9))
print(pi)
Style How you call it Strength
import math math.sqrt(9) Clear source; fewer name clashes
from math import sqrt sqrt(9) Shorter calls; focused imports
Common Pitfall to Avoid: Do not use from math import * (star import) in student or production code. It dumps every name from the module into your file, which makes it hard to tell where a name came from and can overwrite your own variables. Import the module or list the names you need explicitly.
Name clash example (why clarity matters) 
# Your own function named sqrt
def sqrt(n):
    return "I am a custom message, not a square root!"

# This would replace your function if you did: from math import sqrt
# Better: keep the module prefix so both can coexist
import math
print(sqrt(16))       # custom version
print(math.sqrt(16))  # the real math version → 4.0

Putting It Together: A Small Practical Example

Here is a short program that combines both import styles. Read it carefully and notice where the module name is required and where it is not.

Ministry camp lottery helper 
import math
from random import choice, randint

# Students signed up for a midweek activity
students = ["Ava", "Noah", "Grace", "Eli", "Sophia"]

# Pick a random helper for snack time
helper = choice(students)
print(f"Snack helper today: {helper}")

# Random table number from 1 to 8
table = randint(1, 8)
print(f"Please sit at table {table}.")

# How many square tables fit along a wall of length 24 (each table 4 units)?
wall_length = 24
table_size = 4
tables_that_fit = math.floor(wall_length / table_size)
print(f"Tables that fit along the wall: {tables_that_fit}")

What to notice:

  • choice and randint were imported by name, so no random. prefix
  • math.floor still needs the math. prefix because the whole module was imported
  • The program reuses well-tested library code instead of inventing random-number logic from scratch

Exploring What a Module Contains

When you are unsure what a module offers, Python gives you two helpful tools:

dir() and help() 
import math

# List many of the names available in the math module
print(dir(math))

# Read documentation for one function (try this in IDLE or a terminal)
help(math.sqrt)
Tip: Official documentation for the standard library lives at docs.python.org/3/library. Learning to look things up is a core programming skill.

Biblical Reflection

Modules teach us that good work is rarely done in isolation. Someone else wrote math.sqrt and random.choice; we receive those gifts and build something new with them. In the same way, God has gifted different people with different abilities so that the whole body of Christ is built up—not so that any one member would have to do everything alone.

When you import a module, you are practicing a kind of humble dependence: admitting that useful tools already exist, and wisely putting them to work. When a brother or sister shares a hymn, a lesson, or a word of encouragement, the church is strengthened by gifts that did not originate with us. Programming with modules is a small picture of that larger truth.

Scripture:
“There are diversities of gifts, but the same Spirit. There are differences of ministries, but the same Lord. And there are diversities of activities, but it is the same God who works all in all. But the manifestation of the Spirit is given to each one for the profit of all.” — 1 Corinthians 12:4–7 (NKJV)

“For as the body is one and has many members, but all the members of that one body, being many, are one body, so also is Christ. … Now you are the body of Christ, and members individually.” — 1 Corinthians 12:12, 27 (NKJV)

May our use of modules remind us to give thanks for the gifts of others—and to offer our own work so that it can bless those who come after us.
